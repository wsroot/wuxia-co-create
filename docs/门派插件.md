# 门派插件编写指南

《长夜安魂曲》区分两层：

| 层 | 含义 | 路径 / id |
| --- | --- | --- |
| **核心解释器** | Cordis 服务 + Schema + 白名单原语；**目录启动可空** | `src/plugins/*`；无出厂玩法 id |
| **长夜包** | 出厂可玩内容（兵刃/丹药/符箓/功法/关卡…）**always-on** | `src/content/changye` · Cordis id `changye` |

全部玩法内容由 Cordis 插件提供（与 Koishi 同一框架），可再挂子插件。生产启动：`bootMenpai()` → `bootOfficialPack()` 显式加载长夜包后才有完整目录。商店兼容展示 id 仍为 `core`（文案「长夜」）；`menpai-core` 仅为遗留兼容壳，**不再**自灌目录。**勿**把 `changye` 塞进 `OPTIONAL_PACKS`。

## 空手（未持兵）

- **空手 = 装备栏没有兵刃**（`equippedWeaponUid` 为空），**不是**目录里的某个 WeaponDef id。
- 框架战斗在空手时使用运行时王八拳招式（`UNARMED_RUNTIME_DEF` / `BARE` 链），不登记为可锻造兵刃。
- 山门不展示、不可锻造「空手」。
- **新档默认全空**：无武器、无心法、无武功、无丹药库存、无符咒、无已知丹方。打怪掉秘籍 / 山门研习后再学。
- 若官方门派要送入门功法或心法，须在插件 `apply()` 或 Config 里**显式赠予**——默认不赠。

## 一、最小示例

```ts
// src/menpai/qingcheng/index.ts
import { Context, Schema } from 'cordis';

export interface Config { damage: number }

export const QingchengMenpai = {
  name: 'menpai-qingcheng',
  inject: ['talismans'],
  Config: Schema.object({
    damage: Schema.number().min(1).max(60).default(16),
  }) as Schema<Config>,
  apply(ctx: Context, config: Config) {
    ctx.talismans.script({
      id: 'qingchengWind',
      steps: [
        { kind: 'banner', text: '灵符', sub: '青城风起', dur: 80 },
        { kind: 'fx', preset: 'ring', at: 'caster', size: 80, color: '#90e0c0' },
        { kind: 'damageRadius', rx: 140, damage: config.damage, kbX: 6 },
        { kind: 'wait', frames: 20 },
      ],
    });
    ctx.talismans.add({
      id: 'qingfengfu', name: '青风符', fogName: '灵符·风??',
      lore: '青城后山的风，吹散近身之敌。',
      tip: '出征：身周风刃 · 推开近敌',
      color: '#90e0c0', cost: { herb: 2, silk: 1 }, fee: 12, stockCap: 3, runCharges: 1,
      scriptId: 'qingchengWind',
    });
  },
};
```

一个大门派可以拆成多个子插件，再由门派插件统一挂载：

```ts
export const BigMenpai = {
  name: 'menpai-big',
  apply(ctx: Context) {
    ctx.plugin(MyWeapons);
    ctx.plugin(MyTalismans);
    ctx.plugin(MyActs);
  },
};
```

写好后在 `src/menpai/index.ts` 的 `OPTIONAL_MENPAI` 里登记一个名字（如 `qingcheng`）。

## 二、可用的内容服务

| 服务 | 登记方法 | 说明 |
| --- | --- | --- |
| `ctx.weapons` | `add(def)` | 兵刃（`WeaponDef`）。不要登记「空手」——空手是未装备状态 |
| `ctx.pills` | `add(def)` | 丹药。`sortie: true` 表示可打入出征丹槽；`effect` 由核心按数据施放 |
| `ctx.materials` | `add(def)` | 材料 |
| `ctx.talismans` | `script(def)` / `add(def)` | 符效时间线 / 灵符 |
| `ctx.stages` | `add(def)` | 幕次关卡，`actIndex` 0 起算 |
| `ctx.acts` | `pool` / `beat` | 掉落/精英偏向；幕间字幕；`ActPool.kit` **开放 string** 软引用 `ctx.bossKits`（与 `Stage.boss.kit` / `EnemyDef.kitId` 对齐，Act1.5） |
| `ctx.skills` | `add(def)` | 外功。`effects` / `castKind` / `attackKey`（**只认** `ctx.attacks` id，缺则「招式未备」soft-skip；不再回退裸 BARE 表）/ `attackChain`（同目录 id）；被动可标 `profOn` |
| `ctx.neigong` | `add(def)` | 内功心法 |
| `ctx.armorSets` | `add(def)` | 防具套装 |
| `ctx.wepAffixes` | `add(def)` | 兵器实例词缀 |
| `ctx.affixes` | `add(def)` | 场地词缀（效果字段 + `primaryWeight` / `secondaryWeight` / `evolveOnly`） |
| `ctx.enemies` | `add(def)` | 敌人原型。组装键：碰撞（`colliderId`/内联 `collider`）+ 长相（`silhouetteId`）+ 怎么打（`behaviorId`）。`body` ∈ `axe|shield|archer|spear|gargoyle` **可选**软别名到内置配方；无 `body` 时须三者齐全否则拒登。Boss 可选 `kitId`（`ctx.bossKits`；进战解析见下）。可选 `loot[]` / 负载 `skills`/`gear`/`pills`/`talismans` |
| `ctx.eliteMods` | `add(def)` | 精英词条（可挂 `weaponCounters`） |
| `ctx.titles` | `add(def)` | 战绩称号 |
| `ctx.bossKits` | `add(def)` | Boss 招式权重（kit id → close/far） |
| `ctx.fragments` | `add(def)` | 局内残页（闭式 effect；`eventOnly` 不进普通掉落） |
| `ctx.armorPieces` | `add(def)` | 单件防具底表（与 `armorSets` 套装分开） |
| `ctx.attacks` | `add(def)` | 攻击盒时间轴（`AttackBoxDef`，可选 `combatCue`/`swordQi`）；外功、普攻链、敌人 Behavior `attackKey` **只**软引用本目录；长夜种子自 `playerMoves` PM/BARE + 敌人七内置盒 + Boss 八盒（`claw1`/`claw2`/`claw3`/`gCharge`/`gDive`/`gDiveWave`/`gRoar`/`gFire`）挂 id；盾格挡反击/射箭亦 `getAttackBox`（A4）；石兽 claw/charge/dive/roar/fireball 命中盒亦只经本目录（G5） |
| `ctx.combatStyles` | `add(def)` | 普攻链套路（`CombatStyleDef`/`AttackChainStyle`：`groundKeys`/`branches`/`noChainOpen`/`plungeWaveKey`）；`WeaponDef.combatStyleId` 软引用；缺 id → category bare/blade 默认 → CORE 种子回退 |
| `ctx.poses` | `add(def)` | 攻击姿态关键帧。杂兵攻 `skel.*`、石兽攻 `garg.*` 经 `getPose` 软读（缺则硬表）；玩家 locomotion 可覆盖 `hp.idle`/`hp.idle2`/`hp.run1`/`hp.run2`/`hp.hurt`（`locoPose` 读 strike，缺则硬 `HP.*`；override-only 不灌 CORE）；杂兵通用 locomotion 可覆盖 `sp.idle`/`sp.walk1`/`sp.walk2`/`sp.hurt`（同 helper，缺则硬 `SP.*`；盾/枪/弓特化 idle·walk 仍硬常量）；`getAttackPose` 缺 id → `slash1`（猎人路径，不宜作杂兵/Boss 主路径） |
| `ctx.projectiles` | `add(def)` | 投射物配方（飞行/碰撞/`drawKind`；可选 soft `attackKey` → `ctx.attacks`；缺省：`fireball`→`'gFire'`，其余→`'arrow'`；CORE `fireball` 显式挂 `gFire`）。可选 `hitSfx`（sfx 目录 synth id；命中**替代**默认 hit/hitHeavy，不双播；缺省无则今日音）。**改伤害请挂攻击盒**，勿以为改 hitW/H 即改伤 |
| `ctx.fxRecipes` | `add(def)` | 特效配方（粒子原语 + 色/半径/寿命/个数）；脚本可填 `recipeId` |
| `ctx.sheets` | `add(def)` | 包内图集（`./art/` 相对路径；禁外链；体积极限） |
| `ctx.sfx` | `add(def)` | 音效（`synth` 核心合成器 和/或 `src`+`format` 包内 wav/ogg/mp3；`src` 须 `./art/`，建议 `./art/audio/`；**新音频一律进游戏静态** `public/art/audio/`（Vite `public/`→构建产物 `art/`；馆 tgz **永不**塞音频二进制）；file 优先、无 buffer 回退 synth；示范 `r4a_smoke.wav` / `r4c_tap.{wav,ogg}`） |
| `ctx.volleys` | `add(def)` | 弹幕模板（`skySword`/`thunder`/`waterPulse` 原语） |
| `ctx.silhouettes` | `add(def)` | 剪影配方（长相）：`body`/`baseRig` + 可选白名单 `parts[]`（见下表）；无 parts 时等同旧别名 |
| `ctx.behaviors` | `add(def)` | 行为配方（怎么打）：`body` + 白名单 `steps[]`（见下表）；杂兵 AI 仅 Behavior；`body` 作姿态/碰撞软基线 |
| `ctx.colliders` | `add(def)` | 碰撞体配方（碰撞）：`ColliderProfile` `w`/`h` 必填；可选 `hurtInset`/`gravityScale`；非法拒收。`EnemyDef` 挂 `colliderId` 或内联 `collider`（内联优先）；解释器只写 Body 的 w/h，**禁止任意 JS** |
| `ctx.backdrops` | `add(def)` | 幕氛围（theme 选核心生成器 + 可选色板） |
| `ctx.bossMoves` | `add(def)` | Boss 招式目录（kind → 高风险原语；kit 只加权已登记 id；Gsm3 claw soft：`startupMul`/`recoveryMul`/`damageMul`；walk `frames`=踱步 CD；Gsm4 charge/slam/sweep：`windFrames` 蓄力帧，缺省 38/28/22；slam `radius`/`damage`/`hitstop`、sweep `width`/`damage` 已 soft；Dfr1 roar 复用 `windFrames`（缺省 40）+ 可选 `radius`/`frames`（缺省 300/44）；伤仍 `gRoar`；Dfr2 fireball：`frames`=rise（缺省 34）、`count` 弹数（缺省 3）、`windFrames`=gap（缺省 20；phase2 gap 仍壳 14）、`projectileId` soft（缺省 `fireball`；**不扩** drawKind）；Dfr3 dive：`windFrames`=aim 切下（缺省 68；仍 ÷ spd）+ `radius` 落地波半宽（缺省 150）+ `frames`=recover（缺省 60；仍 ÷ spd）+ 可选 `attackKey` 体/波（缺省 `gDive`/`gDiveWave`；无盒 soft-skip）；`diveAim` 仍免疫；**Dfr4** 示范 `?pack=shixiang` 挂 soft 三招 |
| `ctx.animRecipes` | `add(def)` | 动画积木配方（`AnimStep[]` 白名单；技能 `castAnim` / 符咒 `anim` 引用） |
| `ctx.weaponLooks` | `add(def)` | 兵刃外观积木（`WeaponLookDef.parts` 白名单；`WeaponDef.lookId` / `parts` 引用） |

长夜包（`changye`）Config：`tempScribeId`（↓+技临时符）；另通过 apply 写入 `tempScribeCost` / `bossChestGuarantee` / `directorBpDrop` / `tideClearLoot` / `tideSpawn`（见 `pluginConfig`）。

### 规则

- **id 是存档的一部分**，发布后不要改。读档时找不到的 id 会被丢弃。
- **同 id 覆盖**：新登记替换并保持排序；卸载后门派条目移除，下层恢复。
- **校验**：Schema 不合格则拒绝并打日志，不崩溃。
- **敌人掉落表软引用**：`EnemyDef.loot[]` 里的 id（材料 / 图纸 / 外功 / 心法 / 丹方 / 符咒等）是跨插件软字符串；登记时目录里还没有可以只警告，**击杀掉落时若 live catalog 找不到该 id 则静默跳过，绝不抛错**。
- **符效只能是数据**：步骤见 Schema；不可注入函数或自绘。
- 框架**不**硬编码玩法内容 id（无 `STARTER_WEAPON` / `fist` / 固定丹槽白名单等）。掉落池、出征丹、临时符等从已登记定义或门派 Config 推导。
- 场地词缀亦同：门派挂效果字段与抽取权重；主/次词缀抽取与幕间「改写场地」均从 `ctx.affixes` catalog 按权重过滤，框架内无七大词缀 id 字面量表。
- 游戏界面用江湖口吻，不要出现「插件」「注册」这类词。

## 二附、敌人指定掉落（`EnemyDef.loot`）

可为某个敌人原型挂一张**封闭掉落表**（Schema 校验）。击杀时对每一条独立按 `chance`（0..1）掷骰，与全局材料/图纸/装备/秘籍掉落**叠加**（不替代）。**图纸 / 装备 / 丹方**仅精英或 Boss 击杀才掷（普通杂兵恒 0；精英表内再乘核心乘子）；材料、血晶、秘籍等不受此门槛。

```ts
ctx.enemies.add({
  id: 'qingcheng_bandit', name: '青城山贼', body: 'axe', hp: 55, dropChance: 0.22,
  loot: [
    { kind: 'material', id: 'herb', chance: 0.4, amount: 1 },
    { kind: 'pillRecipe', id: 'heal', chance: 0.04 },
    { kind: 'skill', id: 'qinggong', chance: 0.05 },
    { kind: 'blueprint', id: 'other_menpai_blade', chance: 0.02 }, // 软引用：未加载则跳过；仅精英/Boss
    { kind: 'gear', slot: 'body', setId: 'yexing', chance: 0.03 },
    { kind: 'crystal', chance: 0.2, amount: 4 },
  ],
});
```

| kind | 落地路径 |
| --- | --- |
| `material` | 地面材料拾取 → `bankMaterial` |
| `blueprint` | 图纸拾取 → `bankBlueprint` |
| `skill` / `neigong` | 即时解锁 + 横幅（同全局秘籍） |
| `pillRecipe` / `talismanRecipe` | `unlockRecipe` / `unlockTalismanDrop` + 横幅 |
| `gear` | 未鉴定装备生成（可用 `id` / `slot` / `setId` / `quality` 提示） |
| `crystal` | 血晶球拾取 |

`dropChance` 仍只控制药水；`dropBias` 可保留作材料偏向提示（非必需）。

## 二附乙、敌人负载（技能 / 装备 / 丹药 / 符咒）

可为杂兵原型挂**软引用负载**（Schema 校验）。刷出时核心装配；战斗中在 Behavior / 负载间隙按规则施放。**与玩家共用同一套目录 id**；缺 id 软跳过并 `console.warn` 一次。禁止插件注入任意 JS / Canvas。

```ts
ctx.silhouettes.add({
  id: 'qiangying_vanguard', body: 'spear', baseRig: 'spear',
  parts: [
    { kind: 'mainhand', fromWeapon: true },
    { kind: 'palette', sash: '#c07040', eye: '#e09050' },
  ],
});
ctx.enemies.add({
  id: 'qiangying_vanguard', name: '枪影先锋', body: 'spear', hp: 72,
  silhouetteId: 'qiangying_vanguard',
  skills: [{ id: 'tuci', weight: 2, minRange: 90, maxRange: 220, cooldown: 110 }],
  gear: [{ id: 'pijia' }, { id: 'spear' }],          // 防具数值 + 兵刃换手持剪影
  pills: [{ id: 'heal', when: 'hpBelow', hpFrac: 0.4, once: true }],
  talismans: [{ id: 'qiangying_qiangmang', weight: 1, minRange: 50, cooldown: 150 }],
});
```

| 字段 | 运行时 |
| --- | --- |
| `skills[]` | AI 出招间隙按 weight/距离/CD 选 `SkillDef`；`castKind:'attack'` → `attackKey` 攻击盒打玩家 + `castFx`（施放者=该敌）；`heal` → 自疗；`pojun`/`ningqi`/被动 → 跳过并 warn |
| `gear[]` | 生成时读 `armorPieces`/`weapons`/`armorSets` 数值（HP / 攻% / 防% / `dmgTakenMul`）；**weapons 目录 id 同时覆盖剪影 mainhand**（shape/length/三色/`sprite`/`lookId`/`parts`） |
| `pills[]` | `when: spawn\|hpBelow\|elite`；走 `PillEffect`（heal/invuln/atk·def buff/`whileActive` 光环）；对象是该敌人自身。怒气/内力等玩家字段软跳过 |
| `talismans[]` | CD+距离选符；`TalismanScriptPlayer` 以敌人为 caster、朝向玩家（`damageRadius`/`damageCone`/`spawnVolley`/`knockback` 已支持） |

**AI**：杂兵走通用 `Enemy` + Behavior；`think` 前挂负载钩子。**Boss**：必须 `makeBoss(enemyId, x, params)`（导演 `enterBoss` 已接）；经 catalog（EnemyDef + collider + 既有 bossMoves/kit）组装到 `Gargoyle` 壳。kit 解析（G3）：`stage.boss.kit` → `EnemyDef.kitId` → `actPool.kit` → `'stone'`（不改四幕 CORE actPool 默认数值）。绘制姿态（G4，对齐 X5）：攻击优先 `getPose('garg.'+name)`，缺则 `GARG_ATTACKS`；单帧 idle/walk 等优先 `getPose('garg.'+key)?.strike`，缺则硬 `GP`（**勿**裸调 `getAttackPose`——缺 id → 猎人 `slash1`）。命中盒（G5，对齐 A1）：claw/charge/dive/roar/fireball **只** `getAttackBox`（缺 id soft-skip）；种子在 `entities/boss/bossMoves.ts`（文件名易与 catalog `bossMoves` 混淆）。**禁止** `makeEnemy→null` 旁路；误把 boss id 当杂兵刷时 soft-alias 到 `axe` 并 warn。**Boss 负载 MVP**：装配已接（`makeBoss`→LoadoutHost→gear/spawn pills；HP/承伤 mul；`startAttack` 吃 atkMul）；**空档施放已接**（BossLoad2：`idle`/`walk` 调 `tryCastBossLoadout`；dive/roar/charge 等 active 禁止；成功则跳过本帧 `chooseMove`，kit 权重不变）。**Boss 空档积木（Gsm1–5）**：`EnemyDef.behaviorId`→非空 `steps` 时 idle/walk 调 `tickBossBehaviorGap`（仅 `BOSS_GAP_LOCO_KINDS` 走位/朝向/相位子集；非许可 kind soft-skip，不进招）；空档优先级见「二附丁」；**Boss 可挂积木空档**（示范 `?pack=shixiang` → `shixiang_yexun` → `behaviorId: shixiang_yexun_pace`）；无 steps 的核心 `gargoyle` behavior 与今日一致；招 CD 仍走 kit→`chooseMove`；高风险招（dive/roar/…）仍壳。

**示范**：内容包 `qiangying` → `qiangying_vanguard`（`?pack=qiangying`）——齿轮挂 `qiangying_yingqiang`（`lookId: lookQiangyingRain` 外观积木）；AI/碰撞仍跟 `body:'spear'`。
Boss 负载示范：内容包 `shixiang` → `shixiang_yexun`（`?pack=shixiang`）——`isBoss` 挂 `gear: shixiang_yejia`（夜巡石甲，HP/承伤可见）+ `skills: tuci`（idle/walk 空档施放）；kit 权重不变。Boss 长相示范（BossSil3）：同敌挂自建剪影 `shixiang_yexun`（灰石 `palette`/`scale` + 面纹/甲/颈饰/云披）——`drawGargoyle` 已读 sil，可辨于核心 `gargoyle` 空 parts。Boss 空档积木示范（Gsm5）：同敌挂自建 `behaviorId: shixiang_yexun_pace`（facePlayer + keepDistance 180–280 + circleStrafe/idlePace/flank/phase*；仅 loco 子集）——idle/walk 空档走位可辨于核心无 steps 壳路径；dive 等 active 不被 steps 打断。 Boss 高风险招 soft（Dfr1–4）：**拓扑仍壳、只 soft**——见「二附丁」作者向一表；示范包 `shixiang` **1.3.1** 已挂 `shixiang_roar_swift` / `shixiang_fireball_swift` / `shixiang_dive_swift` 并写入 kit；CORE 三行仍 omit。自验 `?pack=shixiang`。

## 二附丙、剪影积木（`SilhouetteDef.parts`）与随兵刃换手持

剪影是**数据配方**，由核心绘制解释；禁止插件任意 JS / Canvas / 外链 PNG。杂兵走 `drawSkeleton`；**Boss 石兽**仍走唯一入口 `drawGargoyle`（壳内 soft 读 `silhouetteId` → 白名单 parts：`palette`/`scale` + `faceMark`/`ornament`/`armorLayer`/`cloak.color`；缺 sil / 无 parts → 与幕级 tint 今日观感一致）。**不**把 Boss 改调 `drawSkeleton`，**不**扩 `SilhouettePartKind`。

```ts
ctx.silhouettes.add({
  id: 'my_sil',
  body: 'axe',            // AI / 碰撞机体（仍仅五套）
  baseRig: 'axe',         // 默认色板/头饰/步态外观基线（缺省=body）
  parts: [
    { kind: 'mainhand', fromWeapon: true },                 // 优先吃 gear 兵刃
    // { kind: 'mainhand', weaponId: 'silver' },            // 或软引用目录
    // { kind: 'mainhand', shape: 'spear', length: 70, blade: '#d8e8ff', edge: '#a0d0ff' },
    { kind: 'headgear', style: 'bandit' },                  // bandit|hat|topknot|hood|none
    { kind: 'offhand', style: 'none' },                     // blade|shield|none
    { kind: 'torso', style: 'robe' },                       // robe|light|heavy（几何仍共用袍）
    { kind: 'palette', sash: '#a02820', eye: '#e05030' },
    { kind: 'scale', value: 1.05 },
  ],
});
```

| part `kind` | 字段 | 运行时 |
| --- | --- | --- |
| `mainhand` | `fromWeapon?` / `weaponId?` / `shape`+`length`+`blade`/`trail`/`edge` | 手持外观；**gear 中第一个 weapons id 覆盖**此部件 |
| `headgear` | `style` | 覆盖 baseRig 默认头饰 |
| `torso` | `style` | 体态提示（当前几何仍走袍；改色用 palette） |
| `offhand` | `style` | 副手短刃 / 圆盾 / 无 |
| `palette` | 各部位色字符串 | 覆盖 ink 色板 |
| `scale` | `value`（约 0.4..2.5） | 骨骼尺寸乘子 |

**武器覆盖规则**（只改外貌，不影响 AI/攻击盒）：

1. `EnemyDef.gear[]` 中若有 `weapons` 目录 id → 取其外观（`lookId`/`parts` → 程序积木；否则 shape/length/三色/`sprite`）
2. 否则看剪影 `parts` 里 `mainhand`（`weaponId` 或 inline shape）
3. 兵刃外观优先：`WeaponDef.parts` → `lookId`→`ctx.weaponLooks` → 无配方则 shape/length/三色；`sprite`/`spriteOverlay` 仅白名单 `ctx.sheets`。**禁止 URL**
4. 无剪影 parts 且无 gear 兵刃 → 旧 `kind` 硬编码外观（兼容）

未知 `kind`：登记时 Schema/服务拒收；若漏网则绘制时 soft-skip + `console.warn`。

## 二附丁、行为积木（`BehaviorDef.steps`）

行为是**数据配方**，由核心 `behaviorInterp` 解释；禁止插件任意 JS。`body` 仍为兼容别名（选姿态/碰撞基线）；有非空 `steps` 时用积木 tick 驱动杂兵 AI（不为每个配方新建 class）。

**与杂兵差异（一句）**：杂兵 `tickBehaviorSteps` 吃满 18 kind（含 melee/ranged/charge 等招式步）；Boss 石兽 **kit/`chooseMove` 仍裁判出招**，`behaviorId` 非空 steps 仅在 idle/walk **空档**走 `tickBossBehaviorGap`（走位/朝向子集），不替代招池。

### Boss 空档优先级（idle/walk 同帧）

1. `tickEnemyLoadoutTimers`（始终）
2. 有非空 `steps` → `tickBossBehaviorGap`（积木旁路；仅 loco 子集）
3. `tryCastBossLoadout`（成功则跳过本帧 `chooseMove`）
4. kit CD≤0 → `chooseMove`（kind→硬状态）

active（dive/roar/charge/…）：**不**进 2/3/4。

### Boss 空档许可 kind（`BOSS_GAP_LOCO_KINDS`）

源码常量：`src/entities/enemies/behaviorInterp.ts` → `BOSS_GAP_LOCO_KINDS`。非许可 kind **soft-skip**（warn 一次、不抛、不进招、不抢 kit）。

| kind | Boss 空档 | 说明 |
| --- | --- | --- |
| `facePlayer` | ✅ 允许 | 朝向玩家 |
| `keepDistance` | ✅ 允许 | 控距；过近 → `walk`+反向 vx（石兽无 `retreat` case） |
| `idlePace` | ✅ 允许 | 无 keep 时踱步 |
| `circleStrafe` | ✅ 允许 | 环绕走位（仍 idle\|walk） |
| `flank` | ✅ 允许 | 侧翼位移计时；无招式挑子时几乎不粘 |
| `phaseAtHp` | ✅ 允许 | 相位标签（嵌套用） |
| `phaseGate` | ✅ 允许 | 展开嵌套 steps（内层仍受白名单约束） |
| `meleeAttack` / `rangedAttack` / `block` / `charge` / `useLoadout` / `dodge` / `callAlly` / `comboChain` / `retreatBurst` / `taunt` / `idleEmote` | ❌ soft-skip | 招式/动作步；出招仍走 kit→`chooseMove` |

作者可见结论：**Boss 空档能挂** face / keep / pace / strafe / flank / phase*；**不要**指望 melee 等步在石兽空档开火。

**Boss 可挂积木空档（Gsm5 收口）**：内容包给 isBoss 敌挂非空 `behaviorId`→`steps`（上表许可 kind）即可；CORE `gargoyle` behavior **仍可无 steps**（bit-identical 壳路径）。自验：`?pack=shixiang` 进第一幕 Boss「石像夜巡」——空档巡廊控距/环绕可辨；高风险招仍走 kit→壳。


```ts
// Boss 空档积木（Gsm5）：仅挂 BOSS_GAP_LOCO_KINDS；出招仍走 kit
ctx.behaviors.add({
  id: 'shixiang_yexun_pace',
  body: 'gargoyle',
  label: '夜巡空档步',
  steps: [
    { kind: 'facePlayer' },
    { kind: 'keepDistance', idealMin: 180, idealMax: 280, chase: 520, retreatSpeed: 2.4 },
    { kind: 'circleStrafe', radius: 200, speed: 1.2, weight: 0.6 },
    { kind: 'idlePace', speed: 1.0 },
  ],
});
ctx.enemies.add({
  id: 'shixiang_yexun', name: '石像夜巡', isBoss: true, hp: 900,
  silhouetteId: 'shixiang_yexun',
  behaviorId: 'shixiang_yexun_pace', // 非空 → 空档吃积木；CORE gargoyle 可仍无 steps
  kitId: 'shixiang_yexun',
});
```

### Boss 高风险招 soft（Dfr1–4 · 示范已挂）

**拓扑仍壳、只 soft**：`kit`→`chooseMove`→kind 开状态链（`fbRise` / `diveUp` / `roarWind`…）仍在 `Gargoyle` 壳；内容包只挂 `BossMoveDef` 白名单字段调节奏 / 条数 / 半径 / 投射物·盒 id。**不**用 BehaviorStep 发起三招；**不**扩 `BOSS_GAP_LOCO_KINDS`；**不**新建第二石像 class / 第二绘制器；**不**扩 `drawKind`。CORE `dive` / `fireball` / `roar` **可 omit** soft 字段 → bit-identical 今日字面量。

| kind | 字段 | 缺省（今日） | 作者向说明 |
| --- | --- | --- | --- |
| **roar**（Dfr1） | `windFrames` | **40** | roarWind 蓄力帧；clamp 1…180 |
| | `radius` | **300** | 震啸环最大半径；clamp 1…800 |
| | `frames` | **44** | roar active 时长；clamp 1…180 |
| | （伤） | catalog `gRoar` | **勿**用绝对值 `damage` 盖盒 |
| **fireball**（Dfr2） | `frames` | **34** | fbRise 升空帧；clamp 1…180 |
| | `count` | **3** | phase1 弹数；phase2=min(8,base+2)；clamp 1…8 |
| | `windFrames` | **20** | phase1 弹间隔 gap；phase2 gap **仍壳 14** |
| | `projectileId` | **`fireball`** | 目录已有才采纳；缺 Def→fireball；**不扩** drawKind |
| **dive**（Dfr3） | `windFrames` | **68** | diveAim 切下帧；**仍 ÷ spd**；clamp 1…180 |
| | `radius` | **150** | 落地波 areaHit 半宽；高仍壳 90；clamp 1…600 |
| | `frames` | **60** | land→recover；**仍 ÷ spd**；clamp 1…180 |
| | `attackKey` | 体 **`gDive`** / 波 **`gDiveWave`** | 挂同一 id 时体波共用；无盒 soft-skip |


## 九、DLCServer（藏经阁）与商店发现

游戏 DLC 商店会向 **DLCServer**（默认同主机 `:4174`）请求 `catalog.json`；不通则退回内置 `OPTIONAL_MENPAI` / `OPTIONAL_PACKS`。
