## 边界（与壳 AI / kit / loadout 分工）

| 线 | 管什么 | 本蓝图 |
| --- | --- | --- |
| **壳 AI（Gargoyle）** | `chooseMove`、phase/poise/plate、硬招 kind（dive/roar/…） | **保留主权**；负载只在「空档」插一刀，**禁止**替换招池 |
| **kit（bossKits · G3 已收）** | close/far `{ move, weight }`；`resolveBossKit` | **不抢**；kit ≠ loadout；本线不改权重解析 |
| **命中盒 / 姿（G4/G5）** | `getAttackBox` / `garg.*` poses | **不抢** |
| **杂兵 loadout（已通）** | `attachEnemyLoadout` + Behavior `useLoadout` | **复用目录与解释器语义**；适配到 Boss 壳 |
| **Boss 负载（本单）** | isBoss / `makeBoss` 跳过的装配与施放 | 分期 **BossLoad1–3** |
| **behaviorSteps 驱动 Boss（G6）** | 用 Behavior 替换 chooseMove | **勿开**；与本线正交 |
| **债 #12 perch 等** | — | **勿开** |

一句话：**kit 决定「出哪招」；负载决定「额外带什么货 / 间隙放什么」；壳 AI 仍是出招主裁判。**

### 1.2 装配分叉

| 路径 | 负载 |
| --- | --- |
| `makeEnemy`（杂兵） | `attachEnemyLoadout(e, def)` ✅ |
| `makeBoss` | 设 kit / collider / archetypeId / silhouetteId / behaviorId；**无** `attachEnemyLoadout` ❌ |
| `makeEnemy` 误指 isBoss | soft-alias axe；**故意不**走 Boss 负载 |

### 1.3 类型墙（关键）

- 杂兵：`Enemy extends …`，`loadout.ts` API 签名均为 **`Enemy`**。
- Boss：`Gargoyle extends Fighter`（**不是** `Enemy`），AI 在 `chooseMove`，**无** `behaviorSteps` / `useLoadout`。
- 故「抄一行 attach」不够——须 **泛化负载宿主** 或 **Boss 侧薄适配**，否则 TypeScript / 承伤倍率 / 施法 caster 对不上。

### 1.4 杂兵负载已提供的能力（可复用）

| 能力 | 入口 |
| --- | --- |
| 装配 + gear 改 HP/atk/def | `attachEnemyLoadout` / `applyGear` |
| 丹触发（spawn/elite/…） | `firePills` |
| 间隙施放 skill/talisman | `tryCastEnemyLoadout`（Behavior `useLoadout` 或 tick） |
| 承伤 / 出伤倍率 | `loadoutIncomingMul` / `scaleLoadoutAttack` |
| 手持兵刃长相 | `heldWeapon` → silhouette |

Boss 今日：**全部未挂**。

### 1.5 内容侧

- 示范杂兵负载：`qiangying`（`useLoadout` + skills/gear）。
- 示范 Boss：`shixiang`（`isBoss` + kit）；**未**挂 skills/gear 作负载验收（可作 BossLoad3 扩包，或新开最小示范）。

## 2. 建模约定（关键决策）

### 2.1 不把 Gargoyle 改成 Enemy（推荐）

保留 A 档壳。负载状态可：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A. 宿主接口（推荐）** | 抽 `LoadoutHost`（hp/maxHp/loadout/team/…最小面）；`attach*` / `tryCast*` 吃接口；`Enemy` 与 `Gargoyle` 都满足 | 一次拆类型墙；改动面可控 |
| B. Boss 专用并行 state | `Gargoyle.loadout` + 复制薄封装 | 快但双轨易漂 |
| C. 继承改造 | Gargoyle→Enemy | **禁止**（扯壳 AI / 碰撞 / 绘制） |

### 2.2 施放策略（与壳 AI 边界）

| 模式 | 含义 | 建议期 |
| --- | --- | --- |
| **仅装配** | gear/pills spawn 改数值；skills 登记不放 | **BossLoad1** |
| **空档施放** | 仅在 walk/idle 且无 active 招、cooldown 间隙尝试 `tryCast*`；失败不打断 chooseMove | **BossLoad2** |
| **Behavior 驱动** | Boss 改 steps / useLoadout 主权 | **不做**（G6） |

硬约束：dive / roar / charge 等 **active 窗口禁止** 负载打断；cast 失败 = no-op。

### 2.3 kit 与 loadout 禁止混名

- `kitId` / `stage.boss.kit` / `actPool.kit` → **只** `bossKits` 权重。
- `skills[]` 里的 `attackKey` 仍走 `getAttackBox`（与杂兵一致）。
- 文档与 smoke 用词分开，避免「挂了 kit 以为有外功」。

### 2.4 bump

默认 **否**。不改存档 schema；仅运行装配。

## 4. 风险与回退

| 风险 | 缓解 |
| --- | --- |
| 负载施放打断俯冲/震啸 | BossLoad2 硬闸；先交 BossLoad1 无施放 |
| gear HP 与 `baseHp`/`hpScale` 叠乘顺序错 | 对齐杂兵：catalog hp → scale → **再** attach gear |
| `scaleLoadoutAttack` 未进 Boss 出伤 | BossLoad1 明确接 hit 路径或声明「仅承伤/HP」并在完成单写清 |
| 与 kit 文档混淆 | 边界表 + smoke 分断言 |
| 类型重构过大 | 优先最小 `LoadoutHost`；禁止 Gargoyle extends Enemy |

回退：`makeBoss` 恢复不挂 loadout；核心 `gargoyle` 无 skills/gear 时路径应与今日 bit-identical。
