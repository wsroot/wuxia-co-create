## 建议先开 · 验收一句（推进用）

> **先开 Gsm1**：在 **不替换 `chooseMove` / kit 权重** 前提下，为石兽接通「可选 Behavior 旁路」——仅当 `EnemyDef.behaviorId` → `getBehavior` 得到**非空 `steps`** 时，在 **`idle` / `walk`** 调 `tickBehaviorSteps`（或 Boss→LoadoutHost 同型薄适配宿主）；招 CD 到期仍走 kit → `chooseMove` → kind 硬状态。无 steps / 核心 `gargoyle` behavior → **与今日 bit-identical**。`bump=否`。  
> **验收一句**：Cordis isBoss 挂自建 `behaviorId`（如 facePlayer + keepDistance 子集）→ 空档走位/朝向可见吃积木；dive/roar/charge 等 active 不被 steps 打断；无 steps 的核心镇山石兽观感与今日一致；`test:menpai`+`build` 绿。

## 终点（用户）

石兽出厂打法可逐步迁入**白名单积木**（复用 `BehaviorStep` 子集，或等价 **Boss 专用闭集行为图**），内容包用数据改「怎么逛 / 何时出哪类招」，而不改战斗 TS、不挂任意 JS。

**不**一次拆光 `gargoyle.update` 巨型 switch；**不**并 `drawKind` 扩集；**不**开 perch/takeoff；**不**新建第二石像 class / 第二绘制器；**不**把 Oc 出厂内容枚举塞回核心。

## 2. 目标模型（关键决策）

### 2.1 三选一（建议 A）

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A. 复用 BehaviorStep 子集 + Boss 薄宿主（推荐）** | idle/walk（及后期低风险招）走既有 `tickBehaviorSteps`；宿主适配 `facing/x/loadout/…`；高风险 kind 仍 `chooseMove` | 不双轨 DSL；与杂兵文档同表；须处理「非 Enemy」API |
| B. 新 `BossBehaviorStep` / 行为图闭集 | 平行白名单（含 diveWind 等） | 表达力强；双表维护；易膨胀成第二解释器 |
| C. 只数据化参数、拓扑永硬 | 帧数/半径再进 `BossMoveDef` | 减字面量，**不**达「积木换打法」终点 |

**禁止**：任意 JS AI、按内容 id `if (id==='…')`、Gargoyle extends Enemy、废弃 `drawGargoyle`。

### 2.2 与负载施放优先级（Gsm1 须写死）

建议顺序（idle/walk 同帧）：

1. `tickEnemyLoadoutTimers`（已有）  
2. **积木旁路** `tickBehaviorSteps`（若有 steps）— 只做走位/朝向/姿态类持续步；**不**在此期让 steps 发起 dive 级招  
3. `tryCastBossLoadout`（已有）  
4. CD≤0 → `chooseMove`

失败均 no-op。active 状态：**不**进 2/3/4。

### 2.3 bump

默认 **否**。

## 3. drawKind 闭集边界（明确建议）

### 建议：**拆开另债 — 本债不含 drawKind 迁出 / 扩集**

| | 石兽状态机（本债） | drawKind |
| --- | --- | --- |
| **是什么** | A 档壳 AI：状态机 / kind→演出 | Schema **绘制原语闭集** `arrow\|fireball` |
| **落点** | `gargoyle.ts` · `BossMoveKind` | `types.ts` `ProjDrawKind`；`schemas.ts`；`entities/projectile.ts` 按 draw 分支画；`resolver.ts` 斩落箭判定 |
| **Oc 定性** | 另债、本线不迁 | **留核**闭集；出厂投射物**行**已迁包；**扩** = 另开 C 单 |
| **与积木关系** | 直接对象 | **正交**（火球招会**消费** `fireball` 条目，但不等于要扩 drawKind） |

**理由（A/B/C）**：

- **内容枚举**（出厂 id 列表）≠ **永久核心债** → Oc 已搬家。  
- **白名单闭集**（drawKind / BossMoveKind / BehaviorStep kind）= 解释器契约，**优先留核**；要扩就**单独 C 档**还插件原语，勿绑在 AI 重构上。  
- 同债打包 → 验收面混乱（战斗 AI vs 投射物绘制），且 ArrowProj 线已收口、扩 drawKind 无用户刚需。

若日后要第三种弹长相：另开 **`C档-drawKind扩集-…`**，本 Gsm 线**不顺手改** `ProjDrawKind`。

## 5. 风险与回退

| 风险 | 缓解 |
| --- | --- |
| 积木打断俯冲/震啸 | Gsm1 硬闸：仅 idle/walk；与负载同 |
| 积木与 `tryCastBossLoadout` 抢帧 | §2.2 优先级；smoke 分断言 |
| `tickBehaviorSteps` 假定 `Enemy` | 抽最小宿主接口（对齐 LoadoutHost）；禁止 extends Enemy |
| 误扩 BehaviorStep 为「第二 Boss DSL」 | Gsm1–2 **默认不扩 kind**；缺原语另开 C 单 |
| 与旧 G6「全 Behavior 替换 chooseMove」范围漂移 | 本蓝图终点是**分期迁**；Gsm1 **明确保留** kit 选招 |
| 误并 drawKind / perch | §3 + 禁区；PR checklist |

回退：idle/walk 忽略 steps → 今日路径；核心 behavior 无 steps 保持 bit-identical。
