### 1.3 Service / SlotStack（关键：不是 `add`）

| Service | Cordis 名 | API | 存储 |
| --- | --- | --- | --- |
| `ActService` | `'acts'` | **`pool(actIndex, pool)`** / **`beat(fromAct, beat)`** | `SlotStack`：槽位=幕序；后登记覆盖同槽；卸载回退下层 |


（`menpai/core/index.ts`）

## 4. 序列化形状建议与否决项

### 4.1 建议形状（Act1 落地采用）

顶键与 inject 服务名对齐，**嵌套**区分 pool / beat（因无统一 `add`）：

```ts
// DlcContentBody 增量（建议）
acts?: {
  /** 槽位覆盖：actIndex 必填；同槽后登记盖先登记（SlotStack） */
  pools?: Array<{
    actIndex: number;           // 0-based；必填
    kit: string;                 // Act1.5: 开放 string 软引用 bossKits（原 lit 四元）
    tint: 'jade' | 'ink' | 'blood' | 'ash';
    eliteWeights: Record<string, number>;
    dropLean: string[];
    blueprintLean: string[];
    setLean: string[];
    loreLine: string;
  }>;
  /** 幕间字幕：fromAct = 离开的幕序（CORE 为 0→1,1→2,2→3 共 3 条） */
  beats?: Array<{
    fromAct: number;            // 必填
    id: string;
    when: 'betweenActs';        // 远程建议固定；其它 when 应走 stages.beats
    title: string;
    subtitle?: string;
    holdFrames?: number;
    slowmo?: number;
  }>;
};
```

`applyContent` 伪代码：

```ts
if (body.acts?.pools) {
  for (const p of body.acts.pools) {
    const { actIndex, ...pool } = p;
    ctx.acts.pool(actIndex, pool);
  }
}
if (body.acts?.beats) {
  for (const b of body.acts.beats) {
    const { fromAct, ...beat } = b;
    ctx.acts.beat(fromAct, beat);
  }
}
```

注入序：保持 `REMOTE_DLC_INJECT` 中 `'acts'` 与 `'stages'` 邻近即可；apply **体内**宜在依赖目录之后调用（`eliteMods` / `materials` / `armorSets` / `weapons` / `bossKits` 已 add 完再 pool，避免作者引用尚未登记的软 id——软引用运行时本就不强校验，但仍建议文档写「依赖键先灌」）。实务：可把 `acts` 的 apply 放在 `stages` 前后均可（无硬 Schema 外键）；**建议放在 `eliteMods`/`bossKits`/`materials`/`armorSets`/`weapons` 之后、或文件末尾**，与「先目录后槽位」一致。

设计台导出：同构 `content.acts = { pools, beats }`；**不要**塞进 `stages[]` 元素里。

### 4.2 否决项

| 候选 | 否决理由 |
| --- | --- |
| **`add('acts', body.acts as ActPool[])`** | `ActService` **无** `.add`；会运行期失败；与 SlotStack API 不合 |
| **仅数组下标 = 幕序、无 `actIndex` 字段**（`pools: ActPool[]`） | 部分覆盖某一幕时须垫 `null`/重发前缀；与 `StageDef.actIndex` 体例不一致；易 silently 错位 |
| **把 ActPool 字段并进 `StageDef` / stages 导出** | 混淆几何关卡与整幕默认；D/门派文档已强调另线；stages 已远程可灌，再塞会污染已闭环面 |
| **顶键拆成 `actPools` + `betweenActBeats` 且从 INJECT 删 `'acts'`** | 可工作，但与现 INJECT `'acts'`、Cordis 服务名、文档 `ctx.acts` 三处漂移；若采此须同步改 INJECT——**不优先** |
| **Act1 顺手把 `kit` lit 改开放 string** | 有价值，但是 Schema/类型双改；与「先打通灌管」正交——标 **Act1.5 / 另小单**，勿绑死 Act1 验收 |
| **默认实现 perch/takeoff** | 债 #12；Boss 蓝图暂缓；**禁止** |

### 4.3 风险（写入完成单时对照）

1. **覆盖语义**：远程 `pool(0, …)` 盖住长夜第 1 幕默认——与 Cordis 插件 overlay 同型；卸载远程应回退（SlotStack dispose）。Smoke 须在**已载长夜**上下文断言覆盖后的值。  
2. **部分池**：只发 `actIndex:2` 一条 → 仅第 3 幕变；其余仍核心——这是建议形状的优点。  
3. **beats when 误用**：若把 `enter`/`beforeBoss` 写进 `acts.beats`，运行挂在幕间列表，场内找不到——设计台/文档应锁 `betweenActs` 或校验 warn。  
4. ~~**kit lit 拒收自建 id**~~ **Act1.5 已跟进**：`kit` 开放 string；自建 id 可作幕默认；仍软引用（目录缺 id 时运行期按既有 bossKits 缺失路径处理）。  
5. **假通回归**：Act1 落地后须有 smoke 证明 `body.acts` **不再**静默丢；并保留「无 acts 字段的旧包」行为不变。
